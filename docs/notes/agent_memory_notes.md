# Agent Memory 学习笔记

> 学习笔记：从 server-memory 出发，理解 agent 记忆的分层、存取机制与选型思路。
> 配套细节见 [mcp_memory_knowledge_graph.md](mcp_memory_knowledge_graph.md)。

## 1. 第一个实例：server-memory

- **本质**：JSON 文件 + 9 个 CRUD 工具，几百行代码，名字唬人，实现极薄。
- **数据模型三件套**：实体（节点）+ 关系（有向边）+ 观察（挂在实体上的事实条目）。
  教科书说"实体 + 关系"，但 **Observation 才是真正存记忆的地方**。
- **关键认知**：server 完全被动，没有任何自动记忆逻辑。何时存、存什么、
  何时读、搜什么，**全部由模型决定**；模型"会不会想起来去用"很大程度取决于
  system prompt 有没有引导——不提，模型经常根本不用。这是很多人配了记忆
  server 却觉得"没记性"的原因。

## 2. 知识图谱的价值：贵在写入的抽象

- 纯文本记忆（往 notes 文件 append）：写入零成本，但**把理解成本转移到
  每次读取**——"明天"是哪天？和谁有关？模型每次都要现场重新解析。
- 知识图谱：**读取时把理解成本一次性付掉**。写入时模型多做一步抽象
  （把"用户说明天要用 glm 跑评测"拆成实体+关系+观察，"明天"换算成绝对日期），
  理解结果固化成 `from/to/name` 这样的"地址"，之后任何会话都能精确地
  查到、更新到、连到它。
- 一句话：**JSON 存的不是字节，是模型已经理解过的结构。**

## 3. 三种记忆的分层

| 类型 | 内容 | 实例 |
|---|---|---|
| 情景记忆 episodic | 发生过的事件 | 会话 transcript |
| 语义记忆 semantic | 事实、偏好、状态 | Claude Code `memory/` 目录、server-memory |
| 程序记忆 procedural | 怎么做的流程 | skills / SKILL.md |

区分标准：**"知道什么" vs "知道怎么做"**。注意 Claude Code 的 memory
只对应语义记忆，程序记忆在 skills 目录，别混淆。

## 4. 两种存取机制的对照

| | server-memory（图谱 + 工具调用） | Claude Code（markdown + 索引 hook） |
|---|---|---|
| 写入 | 模型拆解成实体/关系/观察 | 模型写成一条事实文件（frontmatter + 正文）|
| 读取 | 模型主动调 `search_nodes` / `read_graph` | 索引常驻 context，模型主动 Read 文件 |
| 检索 | 字符串匹配，无 embedding | 无检索算法，靠模型注意力匹配任务场景 |
| 主权 | 在模型/程序手里 | markdown 用户可看、可改、可删 |

### 索引 hook 的原理

Claude Code 的做法：`MEMORY.md` 索引每行一条摘要，会话启动全文注入 context；
某行和当前任务对上时，模型主动去读对应文件。"想起"**发生在模型的注意力里，
不在任何算法里**——索引那一行是"记忆被想起"的唯一通道，没有它，文件就是
磁盘上的死文件。

写索引摘要的核心手艺：**不是概括内容，是埋触发器**——预测"未来什么请求
出现时应该想起它"，把那个场景的关键词写进去。
- 差：`- [我的偏好](preference.md) — 一些个人偏好`（钩子挂空了）
- 好：`- [PyPI 清华镜像](pypi-mirror-tsinghua.md) — 用户用清华镜像，不要换仓库`
  （触发词和将来请求字面直接重合）

和 embedding 检索的本质区别：索引方案**把检索外包给了模型的上下文理解
能力**——字面重合、语义暗示、甚至情境联想都能触发（这是向量做不到的），
代价是占常驻 context，规模到几百条就崩。

## 5. 领域地图与选型阶梯

| 记忆规模 | 方案 | 代表 |
|---|---|---|
| < 100 条 | 索引注入 + 模型主动读 | Claude Code memory |
| 数百 ~ 数万条 | embedding / 混合检索（+ rerank）| mem0、RAG 类 |
| 海量 | 记忆管理（分页、遗忘、冲突消解）| Letta/MemGPT、Zep/Graphiti |

值得学的方向：

- **嵌入检索**：语义召回（搜"评测"能召回写着 "evaluation" 的记忆）、
  BM25 + 向量混合、粗召回 + LLM rerank。
- **遗忘与冲突消解**：真实使用的真正难点。mem0 在写入时先抽取再与旧记忆
  比对，自动执行 ADD/UPDATE/DELETE/NOOP；Zep/Graphiti 给关系加时间戳，
  会过期。mem0 论文很短，值得读。
- **反直觉判断**：记忆系统的失败大多不是存储问题，而是"该不该写、写多少、
  何时注入"的**策略问题**——存太多污染 context，存太少没记性。策略只能
  靠真实使用去调。

## 6. 下一步：先用手，再深入

把 server-memory 接进 Mini-Agent 真实用一周：

1. system prompt 写明使用策略（会话开始读记忆；用户说出重要事实/计划时主动存）。
2. 每天故意告诉它一些事，观察日志里模型实际调了哪些工具、哪些时候想起来
   哪些时候忘了。
3. 撞出一串真实失败案例后，带着问题去看 mem0/Letta，效率完全不同。
